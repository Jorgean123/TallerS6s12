Ejercicio 1: Cálculo Académico con Servlet y EL

Breve descripción de la lógica implementada en el Servlet:
El Servlet recibe tres notas por POST, valida que sean números entre 0 y 20 con hasta dos decimales y calcula el promedio ponderado con BigDecimal. Para este ejercicio se adoptan los pesos de APF1: Avance de Proyecto Final 1 (30 %), APF2: Avance de Proyecto Final 2 (30 %) y PROY: Proyecto Final (40 %), ya que la ficha no define ponderaciones. La aprobación se fija en 13. El resultado se redondea a dos decimales para mostrarlo; la condición de aprobación utiliza el valor sin redondear. El controlador publica promedio y aprobado mediante setAttribute y realiza forward al JSP. Las entradas inválidas muestran un mensaje y una respuesta HTTP 400.
BigDecimal promedio = n1.multiply(new BigDecimal("0.30"))
    .add(n2.multiply(new BigDecimal("0.30")))
    .add(n3.multiply(new BigDecimal("0.40")));
req.setAttribute("promedio", promedio.setScale(2, RoundingMode.HALF_UP));
req.setAttribute("aprobado", promedio.compareTo(new BigDecimal("13")) >= 0);
Fragmento de código Expression Language (EL) utilizado en el JSP para mostrar el promedio ponderado:
<div class="score">${promedio}<small>/ 20</small></div>

Ejemplo para la evidencia: 16, 15 y 18 producen un promedio de 16.50 y estado Aprobado.

Ejercicio 2: Catálogo Dinámico con JSTL Core (<c:forEach>)

¿Qué atributo de la etiqueta <c:forEach> utilizó para enlazar la lista proveniente del Servlet?
Utilicé el atributo items="${productos}". La expresión EL recupera la lista publicada con req.setAttribute("productos", PRODUCTOS). El atributo var="producto" representa el elemento actual. Sus propiedades se resuelven mediante los getters de la clase Producto.
Fragmento de código de la tabla dinámica con JSTL:
<c:forEach var="producto" items="${productos}">
  <tr>
    <td class="product-code"><c:out value="${producto.codigo}"/></td>
    <td><strong><c:out value="${producto.nombre}"/></strong><small class="d-block muted"><c:out value="${producto.categoria}"/></small></td>
    <td class="text-nowrap">S/ <fmt:formatNumber value="${producto.precio}" minFractionDigits="2" maxFractionDigits="2"/></td>
    <td>${producto.stock}</td>
    <td><c:choose><c:when test="${producto.stock gt 0}"><span class="badge rounded-pill text-bg-success">Disponible</span></c:when><c:otherwise><span class="badge rounded-pill text-bg-danger">Agotado</span></c:otherwise></c:choose></td>
  </tr>
</c:forEach>

El bloque se encuentra dentro de tbody. La biblioteca Core se declara con <%@ taglib prefix="c" uri="jakarta.tags.core" %>. Se usa fmt:formatNumber para presentar los precios y c:choose para indicar disponibilidad. Los seis productos son datos de demostración definidos en el controlador.

Ejercicio 3: Validación Condicional de Acceso (<c:if> / <c:choose>)

¿Cómo evaluó la condición de acceso utilizando JSTL y EL en la vista?
El Servlet valida el nombre y la edad entera entre 0 y 120; luego publica nombre, edad, matriculaActiva y evaluado en el request. En la vista, c:if comprueba si ya hubo una evaluación. Dentro de c:choose, c:when utiliza ${edad ge 18 and matriculaActiva}: el ingreso se permite cuando ambas condiciones son verdaderas. c:otherwise muestra el rechazo, y dos etiquetas c:if explican las condiciones incumplidas. c:out escapa el nombre recibido del usuario. La regla es didáctica, pues la ficha no establece un criterio de acceso; no implementa autenticación real.
<c:if test="${evaluado}">
  <c:choose>
    <c:when test="${edad ge 18 and matriculaActiva}"><div class="access-icon">✓</div><h2>Acceso permitido</h2><p>Bienvenido/a, <strong><c:out value="${nombre}"/></strong>. Cumples las condiciones de ingreso.</p><span class="badge rounded-pill text-bg-success">Participante habilitado</span></c:when>
    <c:otherwise><div class="access-icon denied">×</div><h2>Acceso denegado</h2><p><c:out value="${nombre}"/>, revisa las condiciones pendientes:</p><ul><c:if test="${edad lt 18}"><li>Debes tener al menos 18 años.</li></c:if><c:if test="${not matriculaActiva}"><li>Debes contar con matrícula activa.</li></c:if></ul><span class="badge rounded-pill text-bg-danger">Condiciones no cumplidas</span></c:otherwise>
  </c:choose>
</c:if>

Ejemplos: edad 22 y matrícula activa → Acceso permitido. Edad 17 y matrícula inactiva → Acceso denegado con ambos motivos.
